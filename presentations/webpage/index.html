Навигация по странице

На длинной странице навигация должна помогать пользователю быстро перемещаться между разделами.

Типичные примеры

  • landing page
  • документация
  • определенные статьи на странице
  • страница продукта/товара
  • портфолио

Ссылка может вести не только на другую страницу, но и на конкретный элемент текущей страницы.

Как работает href="#..."?

Ссылка

<a href="#projects">
  Projects
</a>

Цель

<section id="projects">
  ...
</section>

Значение после # — это fragment identifier.

Браузер ищет элемент с соответствующим id и перемещает viewport к нему.

href="#projects" → id="projects" → scroll

Smooth scrolling

По умолчанию браузер может мгновенно переместить viewport. Для навигации по длинной странице часто используется плавная прокрутка. 

html {
  scroll-behavior: smooth;
}

Важно

Мы не создаём анимацию вручную. Браузер сам выполняет переход между текущей позицией scroll и положением целевого элемента.

link → browser scroll → target element

А теперь другая задача

Мы уже умеем отправить пользователя к нужному разделу: 

<a href="#projects">
  Projects
</a>

Но что, если пользователь просто прокручивает страницу?

❓ Как узнать, какой раздел сейчас находится в области просмотра? И как на это отреагировать? Например, можно:

  • подсветить пункт меню;
  • показать анимацию;
  • загрузить данные;
  • запустить счётчик;
  • показать элемент.
Нам нужно не управлять прокруткой, а реагировать на неё.

Intersection Observer

IntersectionObserver — это браузерный API, который сообщает JavaScript, когда элемент пересекается с областью просмотра.

Элемент
↔
Viewport

Важно:

Observer не прокручивает страницу и не выполняет анимацию.

Он только сообщает: «элемент вошёл в область наблюдения» или «элемент вышел из неё».

Что такое viewport?

Viewport — это видимая область веб-страницы внутри окна браузера.

Section 1
Section 2
Section 3
Section 4
VIEWPORT

Вся страница

Что важно понимать?

Страница может быть намного больше, чем область, которую мы видим сейчас. При прокрутке содержимое движется, а viewport остаётся областью, через которую мы смотрим на страницу.

Viewport ≠ вся страница
Viewport — только то, что сейчас видно.

Принцип работы Intersection Observer?

Элемент находится вне viewport
↓
Элемент появляется в viewport
↓
IntersectionObserver сообщает об изменении
↓
JavaScript изменяет состояние страницы
Viewport → событие → состояние → UI

Базовая структура IntersectionObserver

const observer = new IntersectionObserver(
  (entries) => {
    // элемент изменил состояние видимости
  }
);

observer.observe(element);

1. Создаём observer

Передаём функцию, которая будет вызвана, когда состояние пересечения изменится.

2. Начинаем наблюдение

observe() говорит браузеру, какой элемент нужно отслеживать.

Главная мысль: мы не спрашиваем браузер постоянно «где элемент?». Браузер сам сообщает нам об изменении.

Что сообщает Observer?

const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      console.log(entry.isIntersecting);
    });
  }
);

true

Элемент пересекается с viewport.

Он появился в наблюдаемой области.

false

Элемент больше не пересекается с viewport.

Он вышел из наблюдаемой области.

Таким образом, можно реагировать на появление элементов в области просмотра.

5. Меняем состояние UI

Когда мы нашли нужную ссылку, добавляем ей класс active. У остальных ссылок удаляем этот класс. 

links.forEach((link) => {
  link.classList.remove("active");
});

if (activeLink) {
  activeLink.classList.add("active");
}
.menu a.active {
  background: #222;
  color: white;
}

6. Почему меню остаётся видимым даже при прокрутке?

Для этого используем position: sticky. Элемент остаётся в обычном потоке, но при прокрутке «прилипает» к заданной позиции. 

.menu {
  position: sticky;
  top: 20px;
}

В отличие от position: fixed, sticky-элемент остаётся частью своего контейнера.

Parallax: разные скорости движения

Parallax — это эффект, при котором разные слои движутся с разной скоростью относительно наблюдателя.

Scroll
→
Изменяем положение
↓
↓
Background
движется медленнее
vs
Content
движется быстрее

Главное здесь — не сама картинка. Мы создаём иллюзию глубины за счёт разной скорости движения слоёв.

Scroll parallax: структура

В нашем примере есть одна сцена и два слоя: дальний фон и передний план.

<section class="parallax-scene">
  <div class="parallax-background">
    <img src="./img/city1.jpg" alt="" />
  </div>
  <div class="parallax-foreground">
    <img src="./img/city.png" alt="" />
  </div> </section>
.parallax-scene → область, внутри которой находится вся сцена
.parallax-background → дальний слой, например город или небо
.parallax-foreground → передний слой, который находится ближе к пользователю

Главная идея: разные слои двигаются с разной скоростью.

Scroll parallax: CSS слоёв

Чтобы слои можно было накладывать друг на друга, используем абсолютное позиционирование. 

.parallax-scene {
  position: relative;
  height: 130vh;
  overflow: hidden;
}

.parallax-background {
  position: absolute;
  inset: -10%;
  z-index: 1;
}

.parallax-foreground {
  position: absolute;
  inset: 0;
  z-index: 2;
}
position: relative → создаём систему координат для внутренних слоёв
position: absolute → размещаем слои поверх сцены
z-index → определяет порядок слоёв
inset: -10% → увеличиваем фон за пределами сцены, чтобы при движении не появились пустые края

В результате получаем условную систему:

┌─────────────────────────┐
│  background   z-index:1 │  ← дальний слой
│                         │
│  foreground   z-index:2 │  ← передний слой
└─────────────────────────┘

Scroll parallax: отслеживаем скролл

Теперь получаем положение страницы и используем его для расчёта смещения слоёв.

const background = document.querySelector('.parallax-background');

const foreground = document.querySelector('.parallax-foreground');

window.addEventListener('scroll', () => {
  const scrollY = window.scrollY;
  const backgroundOffset = scrollY * 0.2;
  const foregroundOffset = scrollY * 0.4;

  background.style.transform = `translateY(${backgroundOffset}px)`;
  foreground.style.transform = `translateY(${foregroundOffset}px)`;
});
window.scrollY → сколько пикселей пользователь проскроллил страницу
backgroundOffset → рассчитываем положение дальнего слоя
foregroundOffset → рассчитываем положение переднего слоя

Scroll parallax: разная скорость

Именно разные коэффициенты создают ощущение глубины.

const backgroundOffset = scrollY * 0.2;

const foregroundOffset = scrollY * 0.4;
Фон — 0.2

Двигается медленнее относительно скролла. Поэтому визуально кажется более далёким.

Передний план — 0.4

Двигается быстрее фона. Поэтому кажется расположенным ближе.

Чем больше коэффициент, тем сильнее слой смещается относительно движения страницы.

Scroll parallax: что происходит при скролле

Допустим, пользователь прокрутил страницу на 500px. 

const scrollY = 500;

const backgroundOffset = 500 * 0.2; // 100px

const foregroundOffset = 500 * 0.4; // 200px

Страница переместилась на: 500px

Фон переместился на: 100px

Передний план переместился на: 200px

Cлои постоянно меняют своё положение относительно друг друга. Именно это и создаёт эффект параллакса.

Scroll parallax: центрирование переднего слоя

В нашем примере передняя картинка дополнительно центрируется внутри сцены.

.parallax-foreground img {
  position: absolute;
  bottom: 50%;
  left: 50%;
  transform: translate(-50%, 50%);
  width: 100%;
}
left: 50% → перемещаем левый край картинки к центру
bottom: 50% → позиционируем картинку относительно центра по вертикали
translate(-50%, 50%) → компенсируем размеры самой картинки

В итоге картинка располагается относительно центра сцены, а JavaScript уже дополнительно смещает весь передний слой при прокрутке.

Mouse parallax: курсор как источник движения

В нашем примере источником движения становится положение курсора. Мы отслеживаем событие mousemove на всей странице. 

window.addEventListener('mousemove', (event) => {

  const mouseX = event.clientX / window.innerWidth - 0.5;

  const mouseY = event.clientY / window.innerHeight - 0.5;

});
event.clientX

положение курсора по горизонтали

event.clientY

положение курсора по вертикали

Сначала координата курсора приводится к диапазону 0...1, затем 0.5 вычитается, чтобы центр экрана стал точкой 0.

Именно поэтому при движении мыши влево получается отрицательное значение, а вправо — положительное.

Mouse parallax: какие элементы двигаются?

Чтобы элемент участвовал в parallax, ему нужно добавить класс parallax и указать скорость через data-speed. 

<div class="circle circle-1 parallax" data-speed="0.15"></div>

<div class="circle circle-2 parallax" data-speed="-0.1"></div>

<article class="card parallax" data-speed="0.2"
>...</article>
Круг 1
0.15
Круг 2
-0.1
Карточка 02
0.2

Остальные элементы страницы не двигаются, потому что у них нет класса parallax. 

const elements = document.querySelectorAll('.parallax');

Mouse parallax: data-speed

data-speed — это пользовательский data-атрибут HTML. Он позволяет хранить дополнительные данные прямо в элементе. 

<div class="circle parallax" data-speed="0.15"></div>

В JavaScript значение такого атрибута можно получить через element.dataset. 

const speed = Number(element.dataset.speed);

В нашем примере data-speed определяет, насколько сильно конкретный элемент реагирует на мышь.

data-speed="0.15" → небольшое движение
data-speed="0.2" → движение немного сильнее
data-speed="-0.1" → движение в противоположную сторону

Mouse parallax: рассчитываем смещение

После получения координат мыши и скорости элемента рассчитываем его новое положение. 

const x = mouseX * 100 * speed;

const y = mouseY * 100 * speed;

Например, если:

mouseX = 0.5;
speed = 0.2;

то горизонтальное смещение будет:

x = 0.5 * 100 * 0.2;// 10px
положение мыши × сила движения = смещение элемента

Таким образом, мы не задаём конкретную координату элемента. Она постоянно пересчитывается в зависимости от положения курсора.

Mouse parallax: применяем transform

Когда координаты рассчитаны, применяем их к элементу через transform.

element.style.transform = `translate(${x}px, ${y}px)`;

В итоге весь алгоритм нашего примера выглядит так:

mousemove
→
mouseX / mouseY
→
data-speed
→
translate()

Каждый раз, когда мышь перемещается, расчёт выполняется заново и элементы получают новое положение.

CSS Scroll-Driven Animation

Раньше для анимации при прокрутке мы использовали JavaScript и событие scroll. 

scroll
  ↓
JavaScript
  ↓
расчёт позиции
  ↓
style.transform

Современный CSS позволяет связать анимацию непосредственно с прокруткой страницы. 

.card {
  animation: reveal linear both;

  animation-timeline: view();
}

animation-timeline: view()

Главное свойство в нашем примере — animation-timeline: view(). 

.card {
  animation: reveal linear both;

  animation-timeline: view();
}

view() связывает прогресс анимации с положением элемента относительно viewport.

Элемент появляется в области просмотра
↓
CSS увеличивает прогресс анимации
↓
Элемент становится видимым

То есть нам больше не нужно вручную отслеживать scrollY.

animation-range: когда запускается анимация?

Мы можем указать, в какой момент появления элемента должна проигрываться анимация.

.card {
  animation: reveal linear both;
  animation-timeline: view();
  animation-range: entry 0% cover 40%;
}

В нашем примере анимация происходит, когда элемент входит в область просмотра.

А что именно происходит с элементом — описывает обычный @keyframes: 

@keyframes reveal {
  from {
    opacity: 0;
    transform: translateY(250px) scale(0.7);
  }
  to {
    opacity: 1;
    transform: translateY(0) scale(1);
  }
}

Sticky storytelling: фиксируем изображение

Левая часть истории остаётся на экране, пока пользователь прокручивает текст справа. 

.visual {
  position: sticky;
  top: 0;

  height: 100vh;

  display: flex;
  align-items: center;
  justify-content: center;
}

position: sticky позволяет элементу оставаться в заданной позиции во время прокрутки.

Поэтому изображение не уезжает вверх вместе с текстом.

Sticky storytelling: шаги

История разбита на несколько элементов .step.

<section
  class="step active"
  data-state="1"
>
  <div class="step-number">
    STEP 01
  </div>

  <h2>Первый шаг</h2>

  <p>
    Текст первого шага...
  </p>
</section>

Атрибут data-state хранит номер состояния, которое должно быть показано.

data-state="1"
data-state="2"
data-state="3"

Получается простая связь: шаг → состояние → картинка.

IntersectionObserver: какой шаг сейчас виден?

Нам нужно понять, когда очередной .step появляется в области просмотра. 

const observer = new IntersectionObserver(
    (entries) => {
      entries.forEach((entry) => {
        if (!entry.isIntersecting) { // проверяем, пересекается ли элемент с viewport
          return;
        }
        // шаг сейчас виден
      });
    },
    {
      threshold: 0.5
    }
  );

threshold: 0.5 означает, что событие срабатывает, когда примерно 50% элемента находится в области просмотра. 

steps.forEach((step) => {
  observer.observe(step);
});

Теперь observer следит за каждым шагом.

IntersectionObserver: дополнительные параметры

Базовую структуру IntersectionObserver мы уже рассмотрели. Но можно указать параметры, которые позволяют точнее настроить наблюдение. 

const observer = new IntersectionObserver(
  (entries) => {
    // обработка пересечения
  },
  {
    root: null,
    rootMargin: "0px",
    threshold: 0.5
  }
);

root — область, относительно которой определяется пересечение. null означает viewport браузера. В этот параметр также можно передать любой другой элемент, чтобы отслеживать пересечение с ним.

rootMargin — позволяет изменить границы области наблюдения. Например, "100px 0px" расширяет её сверху и снизу на 100px.

threshold — определяет, какая доля элемента должна пересечь область наблюдения, чтобы observer зафиксировал изменение.

Шаг → состояние → новая картинка

Когда новый шаг становится активным, мы получаем его data-state.

const state = entry.target.dataset.state;

Для каждого состояния заранее указана своя картинка:

const images = {
  1: './img/cream.jpg',
  2: './img/cream1.jpg',
  3: './img/cream2.jpg'
};

Затем выбираем картинку по номеру состояния:

product.style.backgroundImage =
  `url("${images[state]}")`;

В результате прокрутка текста управляет состоянием sticky-изображения.

Cursor-following / Spotlight

При движении мыши внутри карточки мы хотим перемещать световое пятно вслед за курсором.

Для этого нам понадобится связать JavaScript и CSS:

координаты мыши → CSS-переменные → pseudo-element → radial-gradient

Это хороший пример того, как JavaScript передаёт данные, а CSS отвечает за визуальный эффект.

Как получить координаты мыши?

Событие mousemove передаёт координаты курсора.

card.addEventListener("mousemove", (event) => {
  console.log(event.clientX);
  console.log(event.clientY);
});

clientX и clientY — координаты курсора относительно viewport. 

viewport
┌──────────────────────────────┐
│                              │
│          🖱                  │
│          ↑                   │
│      clientX / clientY       │
│                              │
└──────────────────────────────┘

Координаты относительно карточки

Но нам нужны координаты не относительно всего viewport, а внутри конкретной карточки. 

const rect = card.getBoundingClientRect();

const x = event.clientX - rect.left;
const y = event.clientY - rect.top;

getBoundingClientRect() возвращает положение элемента относительно viewport. 

rect.left  // левая граница карточки
rect.top   // верхняя граница карточки

Поэтому мы вычитаем положение карточки из положения курсора и получаем координаты внутри карточки.

Передаём координаты в CSS

Полученные координаты можно передать из JavaScript в CSS через пользовательские CSS-переменные. 

card.style.setProperty("--mouse-x", `${x}px`);
card.style.setProperty("--mouse-y", `${y}px`);

В результате у элемента появляются значения:

.card {
  --mouse-x: 180px;
  --mouse-y: 90px;
}

JavaScript больше не отвечает за внешний вид — он только сообщает CSS, где находится курсор.

Создаём свет через ::before

Для света удобно использовать псевдоэлемент ::before. 

.card::before {
  content: "";

  position: absolute;
  inset: 0;

  background: radial-gradient(
    250px circle at var(--mouse-x) var(--mouse-y),
    rgba(120, 180, 255, 0.25),
    transparent 70%
  );
}

radial-gradient создаёт круговой градиент, а CSS-переменные определяют его центр.

Поэтому при изменении --mouse-x и --mouse-y свет перемещается вместе с курсором.

Собираем всё вместе

Теперь вся логика помещается в небольшой обработчик.

const cards = document.querySelectorAll(".card");

cards.forEach((card) => {
  card.addEventListener("mousemove", (event) => {

    const rect = card.getBoundingClientRect();

    const x = event.clientX - rect.left;
    const y = event.clientY - rect.top;

    card.style.setProperty("--mouse-x", `${x}px`);
    card.style.setProperty("--mouse-y", `${y}px`);

  });
});

Получается следующая цепочка:

mousemove → координаты → CSS variables → ::before → radial-gradient

Почему здесь нужен transition?

Без дополнительной настройки свет будет следовать за курсором слишком резко.

.card::before {
  opacity: 0;

  transition: opacity 0.3s ease;
}

.card:hover::before {
  opacity: 1;
}

transition делает изменение прозрачности плавным при появлении и исчезновении эффекта.

При этом само положение света меняется непосредственно вслед за координатами мыши.

Современный HTML: браузер многое умеет делать самостоятельно

Раньше для модального окна часто приходилось писать много JavaScript:

  • открывать и закрывать окно
  • добавлять и удалять классы
  • создавать затемнение фона
  • обрабатывать Escape
  • управлять фокусом

Современный HTML уже предоставляет для этого готовые механизмы.

Например: <dialog> и popover.

<dialog> — модальное окно

Для модальных окон в HTML существует специальный элемент <dialog>. 

<dialog id="modal">
  <h2>Удалить файл?</h2>

  <p>Это действие нельзя отменить.</p>

  <button>Отмена</button>
</dialog>

Это уже не просто <div>. Браузер знает, что перед ним диалоговое окно.

Открываем dialog

У <dialog> есть встроенный метод showModal(). 

<button onclick="modal.showModal()">
  Открыть
</button>

<dialog id="modal">
  ...
</dialog>

Вызов:

modal.showModal();

открывает диалог именно в модальном режиме.

Закрываем dialog

Для закрытия используется метод close(). 

<button onclick="modal.close()">
  Закрыть
</button>

Получается очень простой API:

modal.showModal();
modal.close();

Нам не нужно самостоятельно добавлять класс .active или создавать отдельный механизм открытия.

Что браузер делает за нас?

При использовании showModal() браузер сам обеспечивает часть поведения модального окна.

  • диалог отображается поверх страницы
  • появляется модальный режим
  • фон страницы становится недоступен для обычного взаимодействия
  • Escape позволяет закрыть диалог
  • браузер участвует в управлении фокусом

То есть нам не нужно самостоятельно реализовывать всё поведение модального окна.

::backdrop — затемнение фона

У модального <dialog> есть специальный псевдоэлемент ::backdrop. 

dialog::backdrop {
  background: rgb(0 0 0 / 0.65);
}

Он позволяет стилизовать область позади модального окна.

Поэтому нам не нужно создавать отдельный:

<div class="overlay"></div>

Popover

Popover подходит для небольшого всплывающего дополнительного контента. 

<button popovertarget="info">
  Что это?
</button>

<div id="info" popover>
  Дополнительная информация
</div>

Здесь вообще не нужен JavaScript для базового открытия и закрытия.

Связь создают атрибут popovertarget и id.

Dialog и Popover

<dialog>

Используем, когда пользователь должен взаимодействовать с модальным окном.

  • форма
  • подтверждение действия
  • настройки
  • важное сообщение

popover

Используем для дополнительного всплывающего контента.

  • подсказка
  • небольшое меню
  • дополнительная информация
  • панель действий

Видео на странице

Для размещения видео в HTML используется элемент <video>. 

<video
  src="video.mp4"
  controls
></video>

Атрибут src указывает путь к видео, а controls добавляет стандартные элементы управления:

  • воспроизведение и пауза;
  • громкость;
  • перемотка;
  • полноэкранный режим.

Видео как фон Hero-блока

Видео можно разместить на заднем плане блока, например первого экрана сайта.

<section class="hero">

  <video
    class="hero-video"
    autoplay
    muted
    loop
    playsinline
  >
    <source src="hero.mp4" type="video/mp4">
  </video>

  <div class="hero-content">
    <h1>Creative Studio</h1>
    <p>We create digital experiences.</p>
  </div>

</section>

Важно: muted нужен для автоматического воспроизведения во многих браузерах.

Как сделать видео фоном

.hero {
  position: relative;
  min-height: 600px;
  overflow: hidden;
}

.hero-video {
  position: absolute;
  inset: 0;

  width: 100%;
  height: 100%;

  object-fit: cover;
}

.hero-content {
  position: relative;
  z-index: 1;
}

object-fit: cover заставляет видео заполнить весь блок, сохраняя пропорции.

Контент располагается поверх видео благодаря position и z-index.

Управление видео через JavaScript

Иногда стандартных controls недостаточно. Например, можно сделать собственную кнопку Play / Pause. 

<video id="video" src="hero.mp4"></video>

<button id="toggle">
  Play
</button>
const video = document.querySelector("#video");
const button = document.querySelector("#toggle");

button.addEventListener("click", () => {
  if (video.paused) {
    video.play();
    button.textContent = "Pause";
  } else {
    video.pause();
    button.textContent = "Play";
  }
});

У элемента <video> есть JavaScript API: play(), pause(), paused, currentTime, volume и другие свойства и методы.
